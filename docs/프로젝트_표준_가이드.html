0. 원칙

  • 정본은 파일이다. 이 문서는 요약이다. 표의 "정본" 열이 가리키는 파일이 항상 이긴다. 수치가 의심되면 5절 명령으로 다시 잰다.
  • 새 규칙보다 기존 관례. 아래 명명 규칙은 이미 저장소에 다수로 존재하는 패턴을 문서화한 것이다. 기존 파일을 이 문서에 맞추려 일괄 rename 하지 않는다(Surgical Changes).
  • 디렉터리마다 규칙이 다르다. src/dash(snake_case) · ui/(kebab-case) · schemas/(한글 화면명)는 각자 근거가 있다. 전역 단일 규칙을 강제하지 않는다.
  • 관련 정본: CLAUDE.md(모듈 구조·워크트리), docs/DEV_ENVIRONMENT.md(런타임), .claude/rules/frontend-design-defaults.md(UI 금지 패턴).

구성 방식: 평면 디렉터리 + 접두사(기능) + 접미사(역할)

코딩 규칙의 "기능/도메인별 구성"은 src/dash에서 하위 폴더가 아니라 파일명으로 구현돼 있다. 같은 기능의 파일은 접두사가 같아 정렬 시 붙어 나온다.

ew_result_manage.tsx      ← 화면
ew_result_dialogs.tsx     ← 그 화면의 다이얼로그
ew_result_model.ts        ← 순수 로직
ew_result_model.test.ts   ← 그 로직의 테스트

권고 새 기능도 이 방식을 따른다. 하위 폴더 분리는 한 기능이 5파일을 넘고 다른 기능과 import 를 공유하지 않을 때만 검토한다.

2-3. 테스트 파일 — 규칙이 실행 여부를 결정한다

vitest.config.ts의 include: ['src/dash/**/*.test.ts'] — 이 패턴 밖의 테스트는 에러 없이 실행되지 않는다.
  • 확장자는 .test.ts만. .test.tsx · .spec.ts는 수집되지 않는다.
  • 위치는 src/dash/ 하위만. src/lib/에 둔 테스트는 안 돈다.
  • 대상 파일 옆에 둔다(co-located): foo_model.ts ↔ foo_model.test.ts.
  • 기본 환경은 node. DOM 이 필요한 테스트만 파일 첫 줄에 // @vitest-environment jsdom (현행 3개).

3-4. 환경변수 도입 시 규약 권고

API 연동 등으로 환경변수가 처음 필요해지면 다음을 따른다.

파일추적용도
.env.example추적키 목록 + 더미 값. 새 키를 추가하면 여기에 먼저 적는다
.env.development · .env.production추적비밀이 아닌 모드별 값 (API base URL 등)
.env.local · .env.*.local미추적개인 값 · 비밀
  • 클라이언트 노출 키는 VITE_ 접두사 필수(Vite 규칙). VITE_ 값은 번들에 평문으로 들어간다 — 비밀은 절대 넣지 않는다.
  • 읽는 곳은 한 파일(예: src/lib/env.ts)로 모으고 zod 로 검증한다. 미설정이면 기동 시 명시적으로 throw — 조용한 기본값 폴백 금지.
  • 타입은 src/vite-env.d.ts의 ImportMetaEnv에 선언한다.
  • Vercel 값은 대시보드 Environment Variables 에 둔다(Production / Preview 분리).
// src/lib/env.ts (예시)
import { z } from 'zod';
const Env = z.object({ VITE_API_BASE_URL: z.string().url() });
export const env = Env.parse(import.meta.env); // 누락 시 기동 단계에서 실패
