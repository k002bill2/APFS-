# 농림수산식품모태펀드 투자자산관리시스템 재구축 — AI 기획 지침 (공유용)

> 목적: **여러 기획자가 Claude로 화면을 기획할 때 동일한 표준·결과**를 내고 서로 검증할 수 있도록, 이 프로젝트에서 확립한 규칙과 재현 방법을 한 문서로 공유한다.
> 대상: 기획자(Claude 사용), 개발자. / 근거: `통합_화면_구조도_v1.3.xlsx`(최신 기준) + 팀 합의 표준.

## 0. 한 줄 파이프라인
**엑셀 화면정의서(1행=1 UI요소) → 열(규칙) 해석 → 화면정의 스펙(JSON/MD) 추출 → KRDS 기반 목업(HTML) 생성 → 검증 → 화면 간 GNB/LNB 링크.**

## 2. 확립된 설계 표준 (모든 화면 공통 · 자동 적용)

### 2.1 디자인 시스템 (KRDS 기반)
- 색: KRDS 포인트블루 **#256EF4** 계열, danger #E5484D, 파랑 기운 뉴트럴. 라이트/다크 양쪽 토큰.
- 폰트: 한글 시스템 스택(Pretendard→Malgun 폴백, **웹폰트 CDN 금지**). 숫자 `tabular-nums`.
- 셸: 상단 GNB(모태펀드/자펀드/보고서) + **GNB/LNB 전환 토글** + LNB(대메뉴별 프로그램). 채택 방향 = **모던 필터형**.

### 2.2 컴포넌트 규칙
- **날짜 = 날짜 선택기(picker), 셀렉트박스 금지.** 정밀도별 라벨: `YYYY`=기준년, `YYYY-MM`=기준월, `YYYY-MM-DD`=기준일. 연도 picker는 현재±5 기본+◀▶ 페이징(전 범위). 조회 표시만 라벨 예외.
- **첨부파일 = 드래그앤드롭 + '파일 선택' 버튼**(KWCAG 2.5.7). **첨부 목록은 드롭존 밖 하단 별도 영역**.
- **금액 단위 전환(원/백만원/억원)** = **읽기전용 조회 금액 화면에만**. 등록/수정(CRUD) 있는 관리화면은 제외. base=원 저장 후 포맷.
- **다단(2·3단) 헤더 그리드**는 colgroup/scope로 접근성 처리. 넓은 표는 가로 스크롤 컨테이너(본문 안 밀림).
- 등록/수정은 **단일 폼 2모드**. **PK 필드는 등록 시 편집·중복체크, 수정 시 잠금**.
- **모펀드 표시** = 다중모펀드 옵션 제어. 현재 모펀드 1개(농식품모태펀드)라 **옵션 ON 가정**: 단일이어도 표시(필터는 단일옵션 셀렉트, '전체' 없음), **1개 초과면 옵션 무관 무조건 표시**. 마커 `<!-- 모펀드: … -->`+`data-mf-visible="on"`. 구조도가 모펀드를 배정한 화면에만(미배정 화면엔 넣지 않음).
- **워크플로우(진행형) 화면**: 상태 셀(예: 심사단계 태그)을 직접 클릭 트리거로 쓰지 말 것. **행 선택(라디오) → 선택 행의 단계에 따라 유효 액션 버튼만 활성(단계별 게이팅)**. 상태 컬럼은 표시 전용. 예: 자펀드관리 — 심사단계 신청·선정 행에서만 '선정조합 등록' 활성.
- **확정값(2~3개) 필터 = 칩버튼(라디오형), 셀렉트박스 금지.** '공고관리 정기/수시' 필터가 기준 패턴(`.chipbtn`+`chipGroup()` 헬퍼). 실제 적용 사례(모두 사용자 확인된 값): 데이터기준(운용사보고/월말확정), 연도기준(출자사업연도/결성연도/등록연도 — 단, 종합통계 등 이미 다른 2값 세트로 확정된 화면은 그대로 둠), 계정구분(전체/농식품/수산), 출자/배분 구분.
- **Y/N 값 = 상세/등록 팝업에서는 '예/아니오' 라디오.** O/X 표현이 있는 필드도 동일 계열로 취급하되 그리드 표시 방식(배지 vs 텍스트)은 별도 확인 대상. 개인/법인·국내/해외처럼 상세팝업에 존재하는 이지선다 항목도 셀렉트박스 대신 **라디오버튼**. 개인/법인 라디오 선택에 연동해 사업자번호/주민번호 입력을 **자동 하이픈 마스킹** 처리.
- **한 라벨에 셀렉트박스 2~3개가 나열된 콤보 필드는 항상 개별 필드로 분리**(예: "자펀드/투자기업" 한 라벨 아래 2~3개 select → 운용사/자펀드/투자기업 각각 독립 필드). 단, "구분 토글 + 하위값 동적 리필"(`fillTarget()`형) 패턴은 다른 구조이므로 분리 대상 아님. **필터 표준 순서: 모펀드 → 운용사 → 자펀드 → 계정구분**(해당 필터가 있는 화면 전체 공통 적용).
- 조회 버튼 라벨은 **'조회'로 통일**('확인' 금지). 금액단위(원/백만원/억원) 토글은 **우측 정렬**.
- `.field label{width:...}` 처럼 폭 고정 라벨에는 반드시 `white-space:nowrap`을 같이 지정. 누락 시 라벨 텍스트가 세로로 줄바꿈되는 버그가 환경에 따라 재현됨(2026-09 발견, 전 화면 소급 적용됨).
- 그리드 컬럼(예: NO)을 제거·변경할 때는 같은 값이 **다른 위치(그리드 외 인포카드·상세팝업 등)에도 중복 존재하는지** 함께 확인하고 전부 반영할 것. 한 곳만 고치면 스코프 누락으로 재작업 발생.

### 2.3 용어 표준
- 공통코드를 쓰는 **분류값 = 접미사 `구분`**(계정구분·조합구분·거래구분). 독립 원장/테이블 엔티티는 `구분` 안 붙임.
- **계정구분** = 모펀드(농식품모태펀드) 구성 계정(**농식품투자계정·수산투자계정**). ‘자펀드계정’ 아님.
- `사업년도→사업연도`, `수신발전기금→수산발전기금`, `률/율→률`, `설림→설립`, `건정성→건전성` 등 표기 정규화. (상세: `용어집/00_통합_용어집.md`)
- **`피투자업체`/`피투자기업`/`업체명`/`투자업체명`/`한글업체명`/`약식업체명` 등은 전부 `투자기업`/`한글기업명`/`약식기업명`으로 통일**(전 화면 소급 적용됨). 새 화면에서도 이 명칭만 사용.
- 용어 지시가 오면 **용어집도 즉시 최신화**.

### 2.4 데이터·안내 원칙 (중요)
- **없는 코드/데이터 값을 데모에 생성하지 말 것.** CDTP 필드는 실 코드값만(공통코드 시트 CDDT/DSCP·실데이터 P 확인). 모르면 비우고 검토필요 표시.
- **필드↔코드 매핑 혼동 주의(사례)**: **심사단계** = 신청·선정·결성·취소(업무 생애주기, **파생값** — 단일 코드 아님)이며, **결성여부(CDTP:MY=미결성·결성·취소)**·**선정결과(CDTP:SR=선정·탈락·반납·취소)**와 **별개**. "심사단계"를 CDTP:MY로 매핑하면 필터·그리드 어휘가 어긋남. CDTP:MY/SR은 공통코드로 확정이라 ⚠추론마커 불필요.
- **도메인 정합**: 배분(기배분액)·회수·수익은 **납입(A)이 전제**. A=0이면 C=0. 투자배수=(B1+B2+C)/A(A=0 ∞ 케이스는 유효데이터에 없음).
- **화면 내 안내문구는 비고-작성자(O열) 원문만**(`<br>` 줄바꿈). 내가 임의로 지어낸 안내/주석 넣지 말 것(안내는 별도 논의).
- **내가 판단·추론해 넣은 값/항목은 '검토필요' 클릭 마커**로 표시(라벨 옆 ⚠, 클릭 시 "추천 vs 데이터"). AS-IS 근거와 구분.
- **필터가 그리드 표현을 바꾸는 동적 관계**(예: 조회기준 선정/결성년도 → 컬럼 라벨·집계기준 변경)를 반영(엑셀엔 표현 안 됨).

### 2.5 접근성 (KWCAG 2.2 · 공공 필수)
행 선택은 실제 라디오/키보드, 팝업 role=dialog+포커스트랩+ESC+포커스복귀+**배경 스크롤잠금(스크롤바 폭 보정)**, 삭제 alertdialog(기본 취소), 토스트 aria-live, 테이블 caption/th scope, 명도대비 AA, focus-visible, prefers-reduced-motion.

## 3. 작업/운영 규칙
- **엑셀 백업 파일 만들지 말 것**(혼동). 필요 시 버전업(현재 최신 **v1.3**). 원본 오류 정정 시 **노란 음영**. (v1.3 정정 사례: 자펀드관리 프로그램 중복 149행→51행 1벌)
- **UI 검증 통과해야 "완료"**. 검증 항목: 모달 무스크롤·무시프트, 정렬·placeholder 통일, 라이트/다크, 키보드/ESC, 콘솔 에러 없음, 필터/토글 실동작. (렌더는 브라우저로 실제 확인)
- 확정 규칙은 **기존 화면에도 소급 적용**(놓치면 별도 에이전트로).
- 산출물: 화면별 폴더 `NN_화면명\` 안에 `*_spec.json`, `mockup\*.html`. **목업 내비게이션(GNB/LNB)은 로컬 파일 상대경로만 사용**(Claude Artifact 크로스링크 금지 — 2026-08-31부로 로컬 파일이 유일한 기준으로 확정, 아래 §5 참조).
- **시스템 간(예: 모태펀드보고시스템 ↔ 투자자산관리시스템) 크로스링크 금지.** 화면의 GNB/LNB/서브탭 링크는 반드시 자신이 속한 시스템 폴더(`0N_시스템명\`) 내부만 가리켜야 함. 다른 시스템 화면을 참조해야 하면 링크 대신 설계메모로 남길 것.

## 4. 다른 기획자가 "동일 결과"를 내는 방법 (재현 절차)
1. **이 문서(`AI_기획_지침_공유.md`)와 `통합_화면_구조도_v1.3.xlsx`, `용어집/`을 프로젝트에 함께 둔다.**
2. Claude에게 담당 화면(프로그램명)을 주고 다음을 지시:
   > "`통합_화면_구조도_v1.3.xlsx`의 `[프로그램명]` 화면을 `AI_기획_지침_공유.md`의 표준을 모두 적용해 목업으로 만들어줘. 근거 없는 값은 생성하지 말고 검토필요 마커로 표시."
3. Claude는 ① 해당 프로그램 행 추출 → ② 스펙(JSON) → ③ 표준 적용 목업(HTML) → ④ 검증 순으로 진행.
4. **동일성 확인**: 두 기획자의 산출물을 ⓐ 스펙 JSON(항목·컴포넌트·표준적용) 비교 ⓑ 목업 체크리스트(§3 검증) ⓒ 용어집 표준어 일치로 대조. 표준이 문서로 고정돼 있어 결과가 수렴한다.
5. **표준을 개인 Claude 설정에 심는 법**: 이 문서를 프로젝트 루트에 `CLAUDE.md`(또는 그 일부)로 두면 Claude Code가 자동 로드. 팀은 이 MD를 공유·버전관리해 표준을 동기화.

> 이 프로젝트의 Claude 메모리(`~/.claude/projects/.../memory/`)에도 동일 표준이 규칙으로 저장돼 있음. 새 팀원은 이 MD를 근거로 동일 규칙을 자기 세션/CLAUDE.md에 반영하면 됨.

**도구(프로젝트 스킬 `apfs-mockup`)**: 구조도(.xlsx) 읽기·버전 diff는 `.claude/skills/apfs-mockup/scripts/xlsx_read.py`(표준 라이브러리만, openpyxl/pip 불필요) — `sheets`/`dump`/`diff`/`rows` 명령. 버전 비교로 중복오류·변경 추적(예: v1.2 자펀드관리 149행 → v1.3 51행). **목업 검증**은 `file://`가 확장에서 막히므로 로컬 HTTP 서버(`python -m http.server`)로 띄워 브라우저 렌더·콘솔 확인. 설치: `apfs-mockup/install.ps1`(또는 `install.sh`).

## 5. 현재 완료 화면 (참조 레퍼런스)
**로컬 파일이 유일한 기준(Single Source of Truth)이다.** 2026-08-31부로 Claude Artifact 링크는 전 화면에서 제거했으며 더 이상 내비게이션 대상이 아니다(에디트해도 자동 동기화되지 않아 stale해지는 문제로 폐기). 완료 화면은 폴더 구조로 참조한다:
- `01_투자자산관리\` — 투자심의관리·수시보고·자펀드관리·출자배분관리·투자기업정보 등
