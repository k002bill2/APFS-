# 라우트·파일명 가이드

> APFS 개발팀 참고 문서. 화면을 추가하거나 이름을 바꿀 때 이 문서를 따른다.
> 기준: 2026-10-14 한글 route·파일명 전면 영문 전환(브랜치 `refactor/english-routes`).
> 회귀 가드: `src/dash/route_alias.test.ts`. 상위 규약: [`프로젝트_표준_가이드.html`](프로젝트_표준_가이드.html) 2절.

## 0. 세 줄 요약

1. **화면에 보이는 것은 한글, 코드가 쓰는 이름은 영문.** 메뉴 라벨·화면 제목·엑셀 파일명은 한글이고, route(주소 `#/...`)와 소스 파일명은 영문이다.
2. **route 는 kebab-case, 파일명은 snake_case.** 예: route `gp-report-query` ↔ 파일 `gp_report_query.tsx`.
3. **JSX 가 있으면 `.tsx`, 없으면 `.ts`.** 화면 컴포넌트는 `.tsx`, 데이터·스키마·로직은 `.ts`.

## 1. route(화면 주소)

### 1-1. 규칙

| 항목 | 규칙 | 예 |
|---|---|---|
| 형식 | 영문 소문자 kebab-case. 한글·공백·대문자 금지 | `investee-profile` |
| 위치 | 메뉴 리프의 `path` 필드(`src/dash/data.ts` `MENU`) | `{ label:"투자기업정보(통합)", path:"investee-profile" }` |
| 주소 | 해시 라우팅 `#/<route>` | `http://localhost:5273/#/investee-profile` |
| 화면 없는 리프 | path 는 그대로 부여한다(나중에 화면이 생겨도 주소가 안 바뀜) | 회계 26리프 `acct-*`, `report-guide` |
| 대분류 접두 | 같은 이름이 다른 대분류에 생길 수 있으면 접두를 붙인다 | 회계 `acct-`, 수탁보고 `trust-`, 자펀드 보고 `gp-` |

**왜 영문인가.** 한글 route 는 URL 에서 `%EC%9A%B4...` 로 인코딩돼 공유·로그·북마크에서 읽을 수 없고, 메뉴 라벨을 고칠 때마다 주소·즐겨찾기 키가 같이 바뀌어 끊긴다. 라벨(표시)과 route(식별자)를 분리하면 라벨은 자유롭게 고치고 주소는 고정된다.

### 1-2. route 가 화면으로 이어지는 경로

`app.tsx` 가 route 문자열로 화면을 고른다. 두 갈래뿐이다.

| 갈래 | 조건 | 등록 위치 |
|---|---|---|
| 전용 페이지 | `app.tsx` 에 `else if (route === "<route>") page = <Comp …/>` 분기가 있음 | `app.tsx` |
| 스키마 페이지 | 분기가 없고 `PageSchema.route` 가 같은 스키마가 레지스트리에 있음 → `GenericListPage` 가 그린다 | `schemas/index.ts` 의 `ALL` |

둘 다 없으면 `DEFAULT_SCHEMA` 의 가짜 그리드가 뜬다(화면 없는 회계 리프가 이 상태). 메뉴 밖 화면(`portfolio-performance` 등)은 제목을 메뉴에서 못 찾으므로 스키마의 `title` 을 쓴다(`generic_list.tsx` `findMenuContext`).

### 1-2-1. 메뉴 밖 화면 목록 (2026-10-19 실측)

`app.tsx` 분기 + `ALL_SCHEMAS` 의 route 중 `MENU` 리프 `path` 에 없는 것. LNB 에 안 보이며 해시 주소나 화면 안 링크로만 열린다.

| route | 화면 | 진입 | 분류 |
|---|---|---|---|
| `designsystem` | 디자인 시스템 | GNB 버튼(`shell.tsx`), 첫 진입 기본값 | 앱 전용 |
| `schedule` | 일정·알림 센터 | 대시보드 "오늘 일정·알림" 위젯 | 앱 전용 |
| `editor` | 문서 편집기 | 해시 직접 입력만 | 앱 전용 |
| `login` · `onboarding-issue` · `onboarding-invite` | 로그인·발급/초대 온보딩 | 해시 직접 입력 (Shell 없음) | 앱 전용 |
| `monthly-report` | 월간보고 팝업 | 정기보고에서 `window.open` (Shell 없음) | 앱 전용 |
| `portfolio-performance` | 투자 성과·포트폴리오 | 대시보드 위젯·퀵메뉴(`data.ts`) | 메뉴 밖 스키마 |
| `custody-confirm` | 자펀드 수탁관리(확정) | `custody-verify` 리프의 확정 탭 | 리프 탭 |
| `report-form` | 보고양식관리(S1_09) | **진입점 없음** | 고아 — 유지 |
| `report-update-info` | 보고 업데이트정보(S1_10) | **진입점 없음** | 고아 — 유지 |
| `annual-invest-status` | 연도별 투자현황 | **진입점 없음** | 고아 — 유지 |

**고아 3개는 그대로 둔다(2026-10-19 사용자 결정).** `report-form`·`report-update-info` 는 #151(메뉴를 시트와 1:1 정합)에서 리프가 빠졌고 코드만 남았다. 정본 시트에 리프가 다시 생기면 메뉴에 `path` 만 붙이면 된다. 지우자는 제안은 이 결정을 뒤집는 것이므로 사용자 지시 없이 하지 않는다.

반대 방향(메뉴엔 있고 화면이 없는 리프)은 1-1 "화면 없는 리프" 행 참조 — `DEFAULT_SCHEMA` 그리드가 뜬다.

### 1-3. 화면이 자기 route 를 아는 곳

즐겨찾기 별(★)이 route 로 동작하므로 화면 코드도 route 를 안다. **라벨을 route 자리에 넣지 않는다.**

| 화면 형태 | route 를 넣는 자리 |
|---|---|
| `GridFrame` 직접 사용 | `favRoute="<route>"` |
| `RiskPage` (조기경보·수탁보고·자펀드 보고 계열) | `route="<route>"` (`label` 은 한글 제목) |
| `TablesPage` 설정 | `{ label: '한글 제목', route: '<route>' }` |
| 스키마 | `route: '<route>'`, `title: '한글 제목'` |
| 폼 모달 스키마(`kind:'form'`) | `route: '<화면 route>/<폼>'` — 내비게이션 주소가 아닌 **스키마 id**. 예 `subfund/proposal`, `litigation-manage/release` |

## 2. 파일명

### 2-1. 규칙

| 위치 | 규칙 | 예 |
|---|---|---|
| `src/dash/**` 화면·모델·스키마 | 영문 snake_case + 역할 접미사 | `gp_report_query.tsx`, `audit_log_model.ts` |
| 스키마 파일 | route 를 snake_case 로 | route `subfund-notice-manage` → `subfund_notice_manage.ts` |
| 전용 페이지를 보조하는 스키마 | `<페이지이름>_schema.ts` (같은 이름의 `.ts`/`.tsx` 공존 금지) | `investee_profile.tsx` + `investee_profile_schema.ts` |

| 폴더 | 메뉴 도메인/중분류 영문 약어 | `iam/ent/`, `ews/alert/`, `sfr/regularreport/` |

**코드 식별자도 영문.** 스키마 import 별칭은 `s` + 파일명 PascalCase(`import { schema as sGpSpec } from '../iam/gp/gp_spec'`), 상수는 camelCase/UPPER_SNAKE(`occasionalColumns`). 한글 식별자(`s운용사명세서`, `수시보고Columns`)는 쓰지 않는다.

**한글 파일명 금지.** `src/dash` 아래 한글 파일명, 한글 스키마 route(폼 id 포함), 한글 스키마 import 별칭이 생기면 `route_alias.test.ts` 가 실패한다.

**예외 — 원문 목업은 한글 그대로.** `docs/mockups/**` 의 HTML(예 `S1_33_전체_투자실적.html`)은 현행시스템에서 받은 원본이고, 코드의 `출처:` 주석·`provenance.captureFile` 이 그 이름을 가리킨다. 이름을 바꾸면 출처가 전부 끊기므로 바꾸지 않는다. `docs/` 의 사람이 읽는 문서도 한글 파일명을 허용한다.

## 3. `.ts` 와 `.tsx`

### 3-1. 기준

**JSX(`<Button />` 같은 마크업)가 있으면 `.tsx`, 없으면 `.ts`.** 확장자만 보고 "화면 코드인지, 데이터·로직인지"를 알 수 있게 한다.

| 확장자 | 들어 있는 것 | 예 |
|---|---|---|
| `.tsx` | 화면 컴포넌트, 팝업, 셸 | `gp_report_query.tsx`, `investee_profile.tsx`, `shell.tsx` |
| `.ts` | 스키마(`PageSchema`), 순수 로직, 더미 데이터, 설정, 별칭 표 | `gp_spec.ts`, `audit_log_model.ts`, `route_alias.ts` |

### 3-2. 스키마 파일이 `.ts` 인 이유

스키마 파일은 화면을 그리지 않는다. `PageSchema` 객체 하나(컬럼·필터·폼 필드·샘플 행)를 내보낼 뿐이고, import 도 `import type { PageSchema }` 하나다. 실제 화면은 공용 컴포넌트 `GenericListPage`(`generic_list.tsx`)가 이 데이터를 받아 그린다.

```ts
// src/dash/iam/gp/gp_spec.ts — JSX 없음, 데이터만
import type { PageSchema } from '../../schemas/types';
export const schema: PageSchema = {
  route: 'gp-spec',          // 영문 route
  title: '운용사 명세서',     // 화면 제목(한글)
  columns: [ /* … */ ],
  // …
};
```

`.ts` 로 두는 실익:

- `.tsx` 에서는 `<T>value` 꼴 타입 단언이 JSX 로 파싱돼 쓸 수 없다(`value as T` 만 가능). 데이터 파일엔 그런 제약이 필요 없다.
- `_model.ts` 는 React import 를 금지한다 — 그래야 `node` 환경 테스트(`vitest`, 기본 env=node)로 DOM 없이 돈다.
- 리뷰어가 파일 목록만 보고 "이 PR 은 화면을 바꿨나, 데이터만 바꿨나"를 구분할 수 있다.

### 3-3. 판단이 애매할 때

- 지금은 JSX 가 없지만 곧 컴포넌트를 넣을 예정 → 넣는 커밋에서 `.tsx` 로 바꾼다(미리 `.tsx` 로 만들지 않는다).
- 컴포넌트와 데이터가 한 파일에 섞이기 시작함 → 데이터를 `_data.ts`/`_model.ts` 로 떼어 낸다.

## 4. 옛 route 호환 — `route_alias.ts`

### 4-1. 무엇을 막나

route 는 브라우저 여러 곳에 저장돼 있다. 키가 바뀌면 이것들이 조용히 끊긴다.

| 저장 위치 | 내용 |
|---|---|
| URL 해시 | 북마크·공유 링크 `#/<route>` |
| `localStorage` `apfs.route` | 마지막에 보던 화면(새로고침 복원) |
| `localStorage` `apfs.history.v1` | 방문기록 |
| `localStorage` `apfs.menu.v3.fav` 등 | 즐겨찾기·바로가기 |

### 4-2. 동작

`src/dash/route_alias.ts` 의 `ROUTE_ALIAS` 가 **옛 route → 현재 route** 표의 단일 정본(SSOT)이다.

- `app.tsx` 가 해시·`apfs.route` 를 읽을 때 `aliasRoute()` 로 승격한다 → 옛 한글 주소로 들어오면 주소창이 영문으로 바뀐다.
- `data.ts` 의 `MenuStore.get()`·`HistoryStore.get()` 이 읽을 때 `aliasRoutes()` 로 승격·중복 제거한다 → 옛 키로 저장된 즐겨찾기도 별이 켜진 채 보이고, 다음 저장 때 영문 키로 바뀐다.
- **1-hop 만 따라간다.** 별칭의 값은 반드시 현재 살아 있는 route 여야 한다(`A→B→C` 연쇄 금지 — 테스트가 막는다).

### 4-3. 언제 별칭을 추가하나

| 작업 | 별칭 |
|---|---|
| 메뉴 **라벨**만 바꿈 | 불필요 — path 를 그대로 두면 끝 |
| **path** 를 바꿈 | 필수 — `"옛 path": "새 path"` 추가 |
| 화면 **삭제** | 필수 — 옛 route 를 가장 가까운 살아 있는 화면으로(안 하면 가짜 그리드) |
| 기존 별칭의 **대상**이 바뀜 | 그 별칭 값도 새 route 로 고친다(1-hop 유지) |

## 5. 작업별 체크리스트

### 5-1. 새 화면 추가

1. 메뉴 리프에 `path:"<kebab-route>"` 를 준다(`data.ts`).
2. 파일을 메뉴 도메인 폴더에 snake_case 로 만든다 — JSX 가 있으면 `.tsx`, 스키마만이면 `.ts`.
3. 전용 페이지면 `app.tsx` 에 `route === "<route>"` 분기를, 스키마면 `schemas/index.ts` `ALL` 에 등록한다.
4. 화면 코드의 `favRoute`/`route` 에 **route**, `title`/`label` 에 **한글 라벨**을 넣는다.
5. `docs/페이지_구성.html` 에 행을 추가한다(생성기 없음 — 손으로).
6. `npx vitest run` — `route_alias.test.ts` 가 한글 route·한글 파일명을 잡는다.

### 5-2. 메뉴 라벨 변경

1. `data.ts` 의 `label` 만 바꾼다. **path 는 그대로.**
2. 화면 제목 4종을 맞춘다: crumbs 마지막·`title`·`cardTitle` / 엑셀 시트명·파일명 / `SheetDescription` / 파일 머리 주석.
3. 메뉴 문서 재생성: `python3 scripts/menu-doc/gen_md.py …`, `gen_diff.py …` (README 참조).

### 5-3. path(route) 변경

1. `data.ts` 의 `path` 를 바꾼다.
2. `route_alias.ts` 에 `"옛": "새"` 를 추가하고, 옛 값을 대상으로 가진 기존 별칭도 새 값으로 고친다.
3. `app.tsx` 분기 / 스키마 `route` / 화면의 `favRoute`·`route` 를 같은 값으로 바꾼다.
4. 테스트에 박힌 route 리터럴을 고친다(`resolveSchema('<route>')` 등).

### 5-4. 화면 삭제

1. 파일·분기·스키마 등록을 지운다.
2. 옛 route 를 `route_alias.ts` 에서 살아 있는 화면으로 보낸다.
