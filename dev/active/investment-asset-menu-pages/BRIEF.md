## 범위

- `src/`의 Vite + React 정본만 변경한다.
- 메뉴 구조/라벨은 `APFS_DATA.MENU`의 현재 이미지 일치 항목을 유지한다.
- 전용 페이지가 이미 있는 자펀드 관리 6개는 중복 재구현하지 않고, 실제 라우트·메뉴 접근성·참조 적합성만 검토한다.
- 현재 `GenericListPage`로 폴백되는 투자기업정보 7개·운용사 모니터링 6개는 대응 HTML을 근거로 전용 페이지/구성으로 승격한다.
- 동일한 운영 패턴은 공통 구성/스키마를 사용해 중복을 줄이되, 각 메뉴는 독립 라우트와 메뉴 문맥·페이지 제목·업무 컬럼을 가져야 한다.
- 한국어 더미 데이터는 `APFS_DATA` 또는 전용 스키마에 두며 마스크 규약(`mn`, `MT`)을 보존한다.
- light/dark, 키보드 조작, 모바일 폭에서 누락/가로 넘침이 없어야 한다.

## 구현 가설 및 결정 기준

1. 19개를 독립 파일 19개로 복제하지 않는다. 공통 운영 셸·그리드/필터/상세 패턴은 재사용한다.
2. 각 화면에서 목업의 업무 정보 구조(제목, 검색/필터 축, 핵심 컬럼, 상태/집계, 상세·등록 여부)를 우선하고, APFS 현재 토큰/공통 컴포넌트/AG Grid 규약으로 재구성한다.
3. `우수투자기업 관리`는 신규 화면으로 명시하고, 선정 등급·선정연도·산업·고용/매출 성과·사후관리 상태 중심의 관리형 목록으로 제안한다. 추정 데이터는 더미임을 코드/화면에서 과장하지 않는다.
4. 원본에서 `(검토 필요)`인 운용사 명세서는 재무제표/재무 정보의 정보 구조를 참고하되, 현재 매핑이 확정 사실이라고 단정하지 않는다.

## 수용 기준

1. 이미지의 3개 대분류/19개 리프가 LNB에서 정확히 노출되고 각 항목을 클릭하면 해당 라우트가 열린다.
2. 투자기업정보 7개·운용사 모니터링 6개는 더 이상 무차별 `GenericListPage` 폴백이 아니며, 경로별 제목·브레드크럼·핵심 필터/컬럼/업무 액션이 구분된다.
3. 자펀드 관리 6개 기존 전용 라우트는 회귀 없이 유지된다.
4. 각 신규 전용 화면은 목업에서 확인한 정보 구조를 재현하며 APFS 토큰과 라이트/다크를 따른다.
5. 메뉴/라우트 일관성과 최소 핵심 화면의 DOM 행동을 자동 테스트한다. 새 행동 테스트는 RED→GREEN 증거를 남긴다.
6. `npm run build`가 통과한다.
7. production preview에서 최소 3개 대표 라우트(각 대분류 1개)와 `우수투자기업 관리`를 브라우저로 확인하고 스크린샷/콘솔 오류/가로 overflow 여부를 기록한다.
